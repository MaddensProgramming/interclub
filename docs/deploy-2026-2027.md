## Automatic behavior after deployment

`updateRoundTimed` remains a first-generation scheduled function in
`europe-west1`, Node 22, every 15 minutes, timezone Europe/Brussels.
`maxInstances: 1` serializes invocations. Existing timeout/memory limits remain.

Before round one opens, it initializes a missing year `2026` with calendars,
clubs and public player lists. The completion marker is written last. An
existing year is left alone while waiting. After opening, an entirely empty
feed causes a logged no-op. Partial/malformed feeds and network errors stop the
import before result writes; the next scheduled invocation tries again.

During the season, all opened rounds are refreshed, including corrections.
Only completed encounters contribute scores. FRBE board/match points are used
directly, with explicit support for all its game result codes. Future fixtures
remain unplayed. 6J displays its special calendar and the notice about results
being handled separately by FRBE.

The import window is 20 September 2026–2 May 2027 inclusive. During the summer,
the scheduler may still invoke the function, but it exits before network or
database access. Extend the configured window if later official corrections
must be imported. This avoids needing to delete the function for each break.

## Avoiding redundant Firestore writes

`buildSeasonDocuments` produces one final value per document. `writeDocuments`
hashes canonical document content: object key order does not matter, array order
does, and dates/timestamps compare at Firestore's microsecond precision. This
removes the previous unconditional overview/calendar/search writes, repeated
player-ID writes and timestamp-only updates.

The year document stores `importFingerprint`, `importPending` and `lastUpdate`.
When the prepared content matches a completed fingerprint, the writer stops
after one root read and makes zero writes. On changed content it reads the
planned documents and writes only differences, plus two root writes marking
pending/completed state. Existing data adopts the fingerprint once; if no data
changes, this preserves the old last-update time.

This optimization assumes the importer owns these season documents. For a
maintenance repair after direct console edits/deletions, call `writeDocuments`
with `{ verifyDocuments: true }`, or remove only the root's `importFingerprint`
field before the next eligible full import. Do not delete the year or its data.
The forced comparison still skips unchanged writes. Before the first round,
the normal scheduler deliberately leaves an already initialized year alone.

The optimization concerns database writes; Firestore reads, storage and other
cloud services can still incur charges. Every set/update is billable as a write,
even when the supplied content is unchanged: [Firestore pricing](https://firebase.google.com/docs/firestore/pricing).
